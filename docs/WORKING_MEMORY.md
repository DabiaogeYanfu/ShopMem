# 工作记忆数据协议

M-LoCoMo 的工作记忆层描述“在某个任务截止时刻，协作者需要保持哪些事实、待办项和约束”。它与长期记忆层分开：`memory_units.jsonl` 保存可长期检索的事实，`working_memory.jsonl` 保存面向当前任务的活动状态。

每个快照必须包含：

- `snapshot_time`：状态截面时间；
- `task_id`：当前工单、异常调查或质量处置任务；
- `active_facts`：当前仍有效且与任务相关的记忆 ID；
- `pending_items`：待执行事项、负责人角色、截止时间和状态；
- `constraints`：当前任务不可违反的条件；
- `source_dialog_ids`：构成该快照的原始证据。

状态更新遵循事件时间线：新事件可以激活、阻塞、确认或覆盖事实；被 `superseded` 的事实不得出现在后续快照的 `active_facts` 中。问题可以询问“截至某时刻当前应记住什么”，并同时要求返回事实、待办项和证据。

正式数据建议以任务/工单为切分单位，禁止同一 `task_id` 的快照跨 train/dev/test。每条样本都应保留原始对话、事件、长期记忆和工作记忆快照，形成可审计的 provenance 链。
